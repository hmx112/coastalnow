# CoastalNow Surfing v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a 10-location Surfing pilot with a 0–100 Surf Conditions Score, conservative Safety Gate, Surfing hub/location pages, bidirectional Tide/Fishing/Surfing navigation, and reuse of the existing Activity refresh pipeline.

**Architecture:** Reuse the existing shared Condition Snapshot and Activity generator. Add a location-aware Activity Registry helper, a Surfing-specific scorer and renderer, then extend the existing build/SEO/navigation dispatchers without adding a new data workflow or provider. Surfing remains limited to a validated allowlist while Fishing continues on all locations.

**Tech Stack:** Python 3.12, stdlib unittest, existing NOAA/NOS/CO-OPS + NOAA NWS collectors, static HTML generation, GitHub Actions, Cloudflare Pages.

**Spec:** `docs/superpowers/specs/2026-09-03-surfing-v1-design.md`

## Global Constraints

- Existing Tide and Fishing URLs must not change.
- No paid surf API and no new external provider in v1.
- Surf Conditions Score is a normalized 0–100 planning metric, not a measured ocean value, safety score, break-specific forecast, skill recommendation, or guarantee.
- v1 score weights are fixed: wave height 30%, wave period 25%, wind 25%, weather 10%, daylight/time of day 10%.
- Tide is contextual and is not included in the v1 Surf Conditions Score.
- Safety Gate always overrides quality score.
- Alert lookup failure is unknown, never equivalent to no alerts.
- Missing wave height or wave period => Limited and suppress headline numeric score.
- Missing wind/core forecast => Unavailable.
- NOT RECOMMENDED priority remains above Limited.
- Only pilot Surfing locations are generated, linked, indexed, and listed in sitemap/hub.
- No NOAA/NWS logos.
- No Pinterest Surfing RSS in v1.
- Existing 3-hour Activity refresh, 1-hour safety-alert refresh, and shared `coastalnow-site-writes` concurrency are reused.

def activity_enabled_for_location(activity: dict, location_slug: str) -> bool:
    if not activity.get("enabled"):
        return False

    return allowlist is None or location_slug in allowlist


def enabled_activities_for_location(location: dict, registry: dict | None = None) -> list[dict]:
    source = ACTIVITIES if registry is None else registry

    ]

- [ ] **Step 3: Implement exact v1 component thresholds**

```python
SURFING_WEIGHTS = {
    "wave_height": 0.30,
    "wave_period": 0.25,
    "wind": 0.25,
    "weather": 0.10,
    "daylight": 0.10,
}
```

Use these deterministic scores:

- Wave height: `<1 ft=35`, `1–<2=70`, `2–4=100`, `>4–6=85`, `>6–8=55`, `>8–10=25`, `>10=0`.
- Wave period: `<5 s=25`, `5–<7=55`, `7–<9=75`, `9–13=100`, `>13–16=85`, `>16=65`.
- Wind: `<=3 mph=100`, `>3–8=90`, `>8–12=70`, `>12–18=45`, `>18–25=20`, `>25=0`.
- Weather precipitation: `<=20%=100`, `>20–40=80`, `>40–60=55`, `>60=30`; subtract 25 for heavy/torrential rain text but never below 0.
- Daylight: civil dawn through civil dusk `100`; the hour immediately outside civil twilight `60`; otherwise darkness `35`. Darkness by itself is not a hard stop.

Safety Gate:

- Hard-stop active `Tsunami Warning`, `Hurricane Warning`, `Tropical Storm Warning`, `Storm Surge Warning`, `Extreme Wind Warning`, `Severe Thunderstorm Warning`, `High Surf Warning`, `Special Marine Warning`, `Coastal Flood Warning`.
- `Rip Current Statement`: if headline/description contains `high rip current risk`, hard-stop; otherwise cap 39.
- `Small Craft Advisory`: cap 69.
- `Dense Fog Advisory`: penalty 15.
- `Coastal Flood Advisory`: cap 59.
- Sustained wind >=40 mph or gust >=50 mph: hard-stop; >=30/40: cap 39; >=25/35: cap 59.
- Wave exposure index is `height_ft * sqrt(period_s / 8)`: `<5` no action; `5–<7.5` penalty 8; `7.5–<10.5` cap 69; `10.5–<13.5` cap 39; `>=13.5` hard-stop.
- If forecast condition text contains `thunderstorm`, cap 39.

Confidence:

- Failed/unknown alert safety state => `Unavailable`.
- Missing wind or precipitation/core forecast => `Unavailable`.
- Missing wave height or wave period => `Limited`.
- Stale forecast/marine freshness or non-high/medium eligible freshness => `Limited`.
- Otherwise => `High` when all required inputs are fresh; `Medium` when the existing freshness model permits normal scoring but not High.

Reuse `weighted_score`, `SafetyDecision`, `group_local_days`, `best_continuous_window`, and `assess_snapshot_freshness` patterns from Fishing. Daily summaries rank only `ranking_eligible` rows. If any active row/day summary hard-stops, `NOT RECOMMENDED` outranks Limited.
